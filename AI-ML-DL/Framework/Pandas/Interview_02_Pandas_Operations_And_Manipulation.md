# Pandas Operations and Manipulation Interview Questions

## Q1: What is the difference between loc and iloc?

**A1:** loc is label-based indexing that uses row and column labels to select data, while iloc is integer position-based indexing that uses zero-based integer positions. loc includes the end point in slicing (inclusive), so df.loc[0:5] includes row 5, whereas iloc excludes the end point (exclusive), so df.iloc[0:5] includes rows 0-4. loc works with the actual index labels, which may not be sequential integers, while iloc always works with positions regardless of the index values. Use loc when you know the labels and want label-based selection, and use iloc when you need position-based selection or when working with integer positions. Both support boolean arrays, single values, slices, and lists of labels or positions.

## Q2: When should you use at/iat versus loc/iloc?

**A2:** at and iat are optimized accessors for accessing a single scalar value, while loc and iloc can access single values, slices, or arrays. at is label-based (like loc) and iat is position-based (like iloc). The key advantage of at/iat is performance: they are faster for accessing or setting a single value because they bypass some overhead of loc/iloc. However, at/iat can only access a single cell, whereas loc/iloc can select multiple rows, columns, or both. Use at/iat when you need to get or set a single value and performance matters, especially in loops. Use loc/iloc when you need to select multiple values, use boolean indexing, or need the additional functionality they provide. For single value access in tight loops, at/iat can be significantly faster.

## Q3: How does boolean indexing work with &, |, ~ and parentheses?

**A3:** Boolean indexing in Pandas uses boolean arrays or Series to filter data. When combining multiple boolean conditions, you must use bitwise operators (& for AND, | for OR, ~ for NOT) instead of Python's logical operators (and, or, not). This is because Python's logical operators don't work element-wise on arrays. Parentheses are crucial because bitwise operators have higher precedence than comparison operators. For example, (df['A'] > 5) & (df['B'] < 10) requires parentheses around each condition. Without parentheses, df['A'] > 5 & df['B'] < 10 would be evaluated incorrectly. The ~ operator negates a boolean array. Always wrap each condition in parentheses when combining them to ensure correct evaluation order and avoid ambiguity.

## Q4: What are the advantages of the query() method?

**A4:** The query() method allows you to filter DataFrames using string expressions that are more readable than boolean indexing, especially for complex conditions. It supports Python-like syntax and can reference column names directly without quotes in simple cases. Query expressions can be more concise than equivalent boolean indexing, and they're particularly useful when conditions are stored as strings or come from user input. The method can also be faster than boolean indexing for large DataFrames because it uses numexpr for evaluation when possible. Query supports local variables using @ prefix, making it useful in functions where you want to filter based on parameters. However, query() is less flexible than boolean indexing for complex operations and may not always be faster, so choose based on readability and your specific use case.

## Q5: How does groupby work internally (split-apply-combine)?

**A5:** GroupBy follows a split-apply-combine pattern with three stages. First, the split stage divides the DataFrame into groups based on the specified keys, creating a GroupBy object that contains information about group membership. Second, the apply stage performs operations on each group independently, such as aggregation, transformation, or filtering. This is where functions like sum(), mean(), or custom functions are executed on each group. Third, the combine stage merges the results from all groups back into a single DataFrame or Series, with the group keys typically becoming the index. This pattern enables efficient parallel processing of groups and is the foundation for all groupby operations. Understanding this pattern helps you write efficient groupby code and choose the right operation (agg, transform, filter, apply) for your needs.

## Q6: What is the difference between agg and transform?

**A6:** agg (aggregate) returns a DataFrame with one row per group, reducing the group to a single value per column. The result has the same number of rows as the number of groups. transform returns a DataFrame with the same shape as the original, broadcasting the aggregated result back to each row in the group. For example, if you group by 'category' and use agg('mean'), you get one row per category. If you use transform('mean'), you get the mean value repeated for each row in that category's group. Use agg when you want summary statistics per group, and use transform when you need to add group-level statistics as new columns while maintaining the original row count. Transform is commonly used for creating features like group means or standardizing within groups.

## Q7: What does groupby.filter do?

**A7:** groupby.filter applies a function to each group and returns only the groups where the function returns True, keeping all rows from those groups. The filter function receives a DataFrame representing each group and must return a boolean value. This is different from regular filtering because it operates at the group level rather than the row level. For example, filter(lambda x: len(x) > 10) keeps only groups with more than 10 rows, and all rows from those groups are included in the result. This is useful for removing groups that don't meet certain criteria, such as groups with insufficient data, groups below a threshold, or groups that don't pass a group-level validation check. Filter maintains the original DataFrame structure but only includes rows from groups that pass the filter condition.

## Q8: What are the differences between merge, join, and concat?

**A8:** merge combines DataFrames based on common columns or indices, supporting various join types (inner, left, right, outer) and allowing specification of left_on and right_on for different column names. join is a convenience method for merging on indices, defaulting to left join and allowing you to specify how to join. concat stacks DataFrames vertically or horizontally based on axis parameter, aligning on index or columns, and doesn't require common keys. Use merge when you need SQL-like joins based on column values, use join when you're working with indices and want simpler syntax, and use concat when you want to combine DataFrames along an axis without matching keys. Merge and join are for combining related data, while concat is for appending or combining independent datasets. Each has different parameters and use cases, so choose based on your data structure and combination needs.

## Q9: What are the types of joins and how do they work?

**A9:** Inner join returns only rows where keys exist in both DataFrames, excluding unmatched rows from either side. Left join returns all rows from the left DataFrame and matching rows from the right, filling missing values with NaN. Right join returns all rows from the right DataFrame and matching rows from the left, filling missing values with NaN. Outer join (full outer) returns all rows from both DataFrames, filling missing values with NaN where keys don't match. Cross join returns the Cartesian product, combining every row from the left with every row from the right, which can create very large result sets. The join type is specified using the 'how' parameter in merge(). Understanding these join types is crucial for data integration tasks, as choosing the wrong type can lead to data loss or unexpected row multiplication. Inner joins are most common, but left joins are useful when you want to preserve all records from a primary table.

## Q10: How does merge_asof work?

**A10:** merge_asof performs an asof merge, which is like a left join but matches on the nearest key rather than exact matches. It's designed for time series data where you want to match each left key with the right key that is less than or equal to it (or greater, depending on direction). This is useful for scenarios like matching timestamps to the most recent event, aligning sensor readings, or joining financial data where exact matches are rare. You specify the key column (usually a datetime) and optionally a direction ('backward' is default, meaning match the nearest key that is <= left key). merge_asof requires the keys to be sorted and supports tolerance parameters to limit how far apart matches can be. It's particularly powerful for time series analysis and event-based data where exact matches are uncommon but approximate matches are meaningful.

## Q11: What is the difference between pivot and pivot_table?

**A11:** pivot reshapes data from long to wide format but requires unique index-column combinations, meaning each combination of index and columns can only have one value. If there are duplicate combinations, pivot will raise an error. pivot_table is more flexible and handles duplicate combinations by aggregating them using an aggregation function (default is mean). pivot_table also supports multiple value columns, multiple index levels, and additional parameters like margins for subtotals. Use pivot when your data is already aggregated or has unique combinations, and use pivot_table when you have duplicates that need aggregation or when you need more advanced reshaping options. pivot_table is essentially a more robust version of pivot that can handle real-world data with duplicates and provides aggregation capabilities.

## Q12: What is the purpose of melt (wide to long transformation)?

**A12:** melt transforms a DataFrame from wide format to long format by converting multiple columns into rows. It's the inverse operation of pivot. Melt takes specified columns (id_vars that stay as columns, and value_vars that become rows) and creates a new DataFrame with fewer columns and more rows. The value columns become a single 'value' column, and a new 'variable' column indicates which original column each value came from. This is useful when you have data with multiple measurements per subject stored as separate columns and need to analyze them together, when preparing data for visualization tools that expect long format, or when converting from spreadsheet-style data to normalized database format. Melt is essential for data tidying and preparing data for analysis tools that work better with long format.

## Q13: What is the difference between stack and unstack?

**A13:** stack converts columns into index levels, moving the innermost column level to become the innermost index level, creating a Series or DataFrame with a MultiIndex. This transforms wide data into long format. unstack does the reverse, moving index levels to column levels, converting long format to wide format. Stack reduces the number of columns and increases the number of rows, while unstack increases columns and reduces rows. Stack is useful when you want to analyze multiple columns together or prepare data for certain operations. Unstack is useful for creating pivot-like structures or preparing data for presentation. Both operations work with MultiIndex DataFrames and are powerful tools for reshaping hierarchical data structures. The choice between stack/unstack and pivot/melt depends on whether you're working with MultiIndex structures or regular columns.

## Q14: How do you handle SettingWithCopyWarning?

**A14:** SettingWithCopyWarning occurs when Pandas detects that you might be modifying a view instead of a copy, which could lead to unexpected behavior. To fix it, explicitly create a copy using .copy() before modifying, use .loc to ensure you're working with the original DataFrame, or chain operations properly. For example, instead of df[df['A'] > 5]['B'] = 10, use df.loc[df['A'] > 5, 'B'] = 10. If you intentionally want a copy, use df[df['A'] > 5].copy()['B'] = 10. With Pandas 2.0's Copy-on-Write enabled by default, this warning is less common, but understanding it helps write safer code. The warning is Pandas' way of alerting you to potential bugs where modifications might not affect the intended DataFrame. Always address the warning rather than suppressing it, as it indicates a potential logic error.

## Q15: What is the difference between sort_values and sort_index?

**A15:** sort_values sorts the DataFrame by the values in specified columns, allowing you to order rows based on data content. You can specify one or multiple columns and choose ascending or descending order for each. sort_index sorts the DataFrame by its index labels, which is useful when the index has meaningful order or when you want to restore a specific index order. Both methods support inplace modification and return sorted DataFrames. Use sort_values when you want to order by data values (like sorting by salary or date), and use sort_index when you want to order by index labels (like sorting by date index or alphabetical order of string indices). sort_index is also useful after operations that may have scrambled the index order, while sort_values is for ordering by actual data content.

## Q16: How do nsmallest/nlargest compare to sort+head in performance?

**A16:** nsmallest and nlargest are optimized methods for finding the N smallest or largest values, and they're generally faster than sorting the entire DataFrame and taking the head. These methods use partial sorting algorithms that don't need to fully sort the data, making them more efficient when you only need a few top or bottom values. For large DataFrames, nsmallest/nlargest can be significantly faster because they avoid the overhead of sorting all rows. However, if you need the data sorted anyway, or if N is close to the total number of rows, sort+head might be comparable or even slightly faster due to different algorithm overhead. Use nsmallest/nlargest when you only need a few top/bottom values and performance matters, especially with large datasets. They also have cleaner syntax and are more readable than sort+head.

## Q17: What does explode do?

**A17:** explode transforms each element of a list-like column into a separate row, replicating the other column values for each exploded element. It's useful when you have columns containing lists, arrays, or Series, and you want to normalize the data so each list element becomes its own row. For example, if a row has ['A', 'B', 'C'] in a column, explode creates three rows with 'A', 'B', and 'C' respectively, with other columns duplicated. Explode works with list-like objects including lists, tuples, Series, and arrays. It's commonly used for handling nested data structures, converting JSON arrays into rows, or normalizing data where multiple values are stored in a single cell. Explode is particularly useful in data cleaning and preparation for analysis or machine learning, where you need one observation per row.

## Q18: What is the difference between drop and pop?

**A18:** drop removes specified rows or columns and returns a new DataFrame (unless inplace=True), allowing you to remove multiple items at once. pop removes a single column, returns it as a Series, and modifies the original DataFrame in-place. drop is more flexible as it can remove rows or columns, supports multiple items, and can work with labels or positions. pop is specifically for columns and is useful when you want to extract a column while removing it from the DataFrame in one operation. Use drop when you want to remove items without needing them, or when removing multiple items. Use pop when you want to extract a column and remove it simultaneously, which is common in data preprocessing pipelines where you separate features from targets. Pop modifies the DataFrame in-place, so be careful if you need to preserve the original.

## Q19: How does reindex work?

**A19:** reindex conforms a DataFrame or Series to a new index, aligning data to the new index labels and filling missing positions with NaN (or a specified fill value). It's useful for changing the index order, adding missing index labels, or aligning multiple DataFrames to the same index. reindex supports various fill methods like 'ffill' (forward fill) or 'bfill' (backward fill) to handle missing values, and it can reindex columns as well using the columns parameter. When reindexing, values are matched by label, not position, so the order of the new index determines the order of the result. This is different from resetting the index, which creates a new default index. reindex is fundamental for time series operations where you need to align data to a specific date range or ensure consistent indexing across multiple datasets.

## Q20: What does the indicator parameter in merge do?

**A20:** The indicator parameter adds a special column to the merged result that indicates the source of each row. When indicator=True or indicator='_merge', a column is added showing whether each row came from 'left_only', 'right_only', or 'both'. This is extremely useful for debugging merges, understanding data quality, identifying unmatched records, and validating that your merge worked as expected. You can also specify a custom column name by passing a string like indicator='source'. The indicator column helps you verify join logic, find records that didn't match (which might indicate data quality issues), and understand the merge results. This is particularly valuable for left or outer joins where you want to see which records matched and which didn't, making it easier to identify missing relationships or data inconsistencies in your datasets.
