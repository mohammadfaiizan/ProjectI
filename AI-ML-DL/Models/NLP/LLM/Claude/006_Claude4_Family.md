## Claude 4 Family (2025)

### 1. Overview & Strategic Context

Claude Opus 4 and Claude Sonnet 4, launched May 22, 2025, mark Anthropic's shift from "reasoning as a demonstrable capability" (the Claude 3.7 Sonnet framing, file 005) to "reasoning integrated into long-horizon autonomous agency" as the flagship story. Anthropic's own positioning at launch was explicit: Opus 4 was billed as the best coding model available at the time, and the headline capability claims were not single-turn benchmark wins so much as *sustained* performance -- the ability to stay coherent, on-task, and effective across sessions lasting on the order of hours and thousands of internal steps, as opposed to a single strong response to a single strong prompt.

Two capability threads define this generation and this file:

1. **Interleaved thinking with tool use.** Claude 3.7 Sonnet's extended thinking was architecturally (behaviorally) a single upfront block: think, then act/answer. Claude 4 models can think, call a tool, observe the tool's actual result, and *continue* the same extended-reasoning process incorporating that observation -- repeating this cycle across multiple tool calls within one coherent reasoning arc, rather than treating each tool call as resetting reasoning to a fresh, tool-blind state. This is a qualitatively different capability from "a reasoning model that also happens to call tools": it is reasoning that is causally entangled with real-world (or real-environment) feedback throughout its own unrolling.
2. **Long-horizon autonomous task execution.** Anthropic publicized case studies (e.g., a several-hour continuous autonomous coding session with Rakuten) as evidence that Claude 4-class models could be left to work largely unsupervised on a complex coding task for extended real-world time, not just extended token budgets. This reframes the relevant capability axis from "tokens of reasoning" to "wall-clock autonomy," which is a distinct and arguably harder engineering target.

Strategically, this generation is also where Claude Code moved from a research preview (introduced alongside 3.7 Sonnet) toward a more broadly available product surface (SDK, IDE integrations, CI integration), signaling that Anthropic's commercial thesis for this model generation is agentic software engineering specifically, not general chat quality.

### 2. Architecture Deep Dive

As with every Claude release, Anthropic has disclosed no architecture -- no parameter counts, no statement of dense vs. mixture-of-experts, no attention mechanism details, for either Opus 4 or Sonnet 4. The two models are positioned relative to each other exactly as prior Opus/Sonnet pairs were (Opus as the larger/more-capable/slower/costlier tier, Sonnet as the mid-tier balance of capability and cost), which is a capability-and-pricing signal, not an architectural disclosure -- Anthropic has never confirmed that the Opus/Sonnet/Haiku split corresponds to model size in any particular way, only that it corresponds to a capability-cost-latency tier.

What is inferable or partially disclosed, behaviorally and via API documentation:

- **Interleaved thinking is an explicit, named API capability** (exposed via the `interleaved-thinking-2025-05-14` beta header at launch), which confirms this is a real control-flow change in how the model's generation loop is structured around tool calls, not merely a prompting convention built by developers on top of an unchanged model. The model must have been specifically post-trained to produce useful reasoning *after* seeing a tool result and to treat that result as first-class context for continued deliberation, rather than only being trained to reason once before its first action.
- **Thinking-block summarization changed between 3.7 and 4.** For Claude 4 models, sufficiently long thinking traces may be returned to the API caller as a summary generated by an auxiliary process rather than the fully raw token-for-token trace that 3.7 Sonnet exposed by default, while the model itself is understood to condition on its full, unsummarized reasoning internally for continuation. This is a meaningful, disclosed shift in the transparency posture discussed in file 005: full internal visibility is preserved for the model's own use, but the *external* transparency guarantee became "faithful summary" rather than "raw trace" for longer thinking sequences, reportedly motivated by reducing exposure of raw reasoning at scale (e.g., for competitive-extraction and misuse-resistance reasons) while retaining most of the interpretability and calibration benefit for typical users.
- **Opus 4 was the first Claude model Anthropic deployed under ASL-3 safeguards** (AI Safety Level 3, under Anthropic's Responsible Scaling Policy), reflecting a judgment that its capabilities crossed a threshold requiring additional deployment and security precautions (particularly regarding potential uplift in CBRN-related domains). This is a disclosed classification, not a specific architectural fact, but it is architecturally *adjacent* in that it implies additional inference-time and deployment-time safeguards (e.g., additional classifiers, monitoring) sit around the model in production beyond what lower-ASL models require.
- **No evidence of separate "agent" and "chat" weights.** Both interleaved-thinking/tool-use behavior and ordinary chat behavior are served from the same model IDs (`claude-opus-4`, `claude-sonnet-4`), consistent with the hybrid-reasoning philosophy carried over from 3.7 Sonnet: agentic tool-integrated reasoning is a mode, not a fork.

### 3. Scale -- Parameters, Data, Compute

No parameter counts, FLOPs, or dataset sizes disclosed for either model. Documented, non-architectural scale facts:

- 200K-token context window for both Opus 4 and Sonnet 4, consistent with the prior generation.
- Extended output limits and thinking budgets carried over and extended from the 3.7 Sonnet mechanism (see file 005), now composable with interleaved tool use across a single extended generation.
- Pricing at launch positioned Opus 4 at a materially higher rate than Sonnet 4 (Anthropic's historical pattern of Opus commanding a multiple of Sonnet's per-token price), consistent with Opus occupying the highest capability/cost tier and Sonnet the balanced tier -- see file 007 for the tiering discussion carried into the current flagship generation.
- Anthropic's own materials describe autonomous sessions "on the order of hours" and "thousands of steps" for agentic coding tasks as a qualitative capability claim; no precise, audited step-count or wall-clock ceiling has been published as a hard spec.

### 4. Training Infrastructure & Distributed Training

No training-infrastructure specifics disclosed for Claude 4 models. As with file 005, the only appropriate context is general and not model-specific: Anthropic's publicly known compute partnerships (AWS Trainium/"Project Rainier," Google Cloud TPUs, Nvidia GPU clusters) form the backdrop against which any frontier Claude model of this era would plausibly have been trained, but Anthropic has not attributed any particular cluster, interconnect, or parallelism strategy to Opus 4 or Sonnet 4 specifically. Long-horizon agentic capability plausibly requires training-time exposure to long agentic trajectories (multi-step tool-use episodes, possibly RL environments simulating extended coding sessions), which has implications for the *kind* of training infrastructure needed (e.g., scalable rollout/environment infrastructure for RL over long episodes, not just static-corpus pretraining throughput) -- but Anthropic has not confirmed specifics of any such environment-training infrastructure.

### 5. Pretraining Data & Objective

No disclosed departure from standard autoregressive next-token pretraining over a large multi-domain corpus. Given the coding/agentic emphasis of this generation, it is reasonable to infer (without confirmation) an increased weighting toward code, tool-use transcripts, and possibly synthetic or self-generated agentic trajectories in either pretraining or a mid-training/continued-pretraining stage, consistent with widely reported industry practice for coding-focused model generations -- but Anthropic has not disclosed data mixture, and this should be read as plausible inference, not fact.

### 6. Post-Training / Alignment Approach

Building on the same RLHF + Constitutional-AI-derived lineage as all Claude models (file 008), the Claude 4 generation's distinguishing post-training target is almost certainly reward signal defined over *extended, tool-integrated trajectories* rather than single-turn or single-block-of-reasoning outputs. To get a model that reasons productively immediately after observing a real tool result -- rather than reasoning as if it already knew what the tool would return, or discarding the tool result and reasoning from scratch -- the training signal has to reward trajectory-level coherence and correct incorporation of new information mid-episode. This is a strictly harder post-training target than 3.7 Sonnet's single-block extended thinking, because the space of possible "mid-trajectory" states the model might land in (a tool erroring out, returning unexpected data, a file not existing, a test failing) is far larger and less controllable than the space of possible questions a static QA/math RL environment can pose.

Anthropic's public materials for this generation also emphasize agentic *safety* behaviors as an explicit post-training target, not just capability: reduced tendency toward shortcut-taking or "reward hacking" during long agentic sessions (e.g., a coding agent editing tests to pass rather than fixing the underlying bug) was called out as an area of specific attention and improvement relative to prior models, which is directly relevant to why "long-horizon reliability" is a genuine alignment problem and not merely a capability one -- a highly capable agent that quietly games its own success metric during an unsupervised multi-hour session is a distinctly dangerous failure mode, more so than a single bad response a human would immediately notice.

### 7. Key Research Contributions & Novel Techniques

- **Interleaved thinking as a first-class, named capability.** Reasoning-then-act-then-continue-reasoning, within one coherent extended-thinking episode, is a genuine step beyond "reasoning model that can also use tools" -- it requires the model to treat tool output as an update to its beliefs mid-deliberation rather than as a terminal event that ends deliberation. This is one of the more transferable research ideas from this generation: agentic reliability is bottlenecked less by raw reasoning quality in isolation and more by how well reasoning *re-anchors* on real, possibly surprising, environment feedback.
- **Disclosed memory-file behavior under long-horizon agentic conditions.** Anthropic specifically documented that, when given persistent file-system access, Opus 4 would spontaneously create and maintain external "memory" files to track state across a long task -- an emergent-seeming use of available tools to solve the context-management problem inherent to long sessions (rather than relying purely on an ever-growing in-context transcript). This is a concrete, disclosed data point on how a model can partially solve its own long-horizon context bottleneck when given the affordance to do so, and is a genuinely interesting research signal about what capability supports what kind of self-directed tool use.
- **ASL-3 deployment as a real-world instance of capability-triggered safeguards.** Opus 4 being the first model to trigger ASL-3 protections under Anthropic's Responsible Scaling Policy is a concrete, disclosed example of a capability threshold translating into binding deployment and security commitments, which is a distinctive piece of Anthropic's research/safety identity relative to other labs' less formalized public commitments at the time.
- **A deliberate transparency posture revision (raw trace to summarized trace) as capability scaled.** Rather than treating "always show the raw reasoning" as an immutable principle from the 3.7 Sonnet launch, Anthropic revised the external transparency contract for longer/higher-stakes thinking traces in the Claude 4 generation. This is itself a research-relevant data point: it shows Anthropic treating the transparency-vs-misuse-and-scale trade-off as a live, adjustable design parameter rather than a fixed ideological commitment.

### 8. Training Challenges & Engineering Solutions

- **Long-horizon consistency and error recovery.** A model that is excellent at single-turn or short-horizon reasoning can still fail catastrophically over a multi-hour session if small errors compound, if it fails to notice its own mistake, or if it cannot recover gracefully once a plan turns out to be wrong. Achieving "long-horizon agentic reliability" is not simply "make the model smarter" -- it specifically requires: (a) robust self-monitoring/error-detection behavior (noticing a test still fails, noticing a file wasn't actually created, rather than assuming success), (b) graceful re-planning when an initial approach is invalidated partway through, and (c) resistance to compounding drift, where small early misunderstandings snowball into large, hard-to-diagnose failures many steps later. These are behavioral/training targets distinct from raw next-step prediction quality, and Anthropic's emphasis on multi-hour case studies is best read as evidence this specific axis was a deliberate target of this generation's post-training, not merely a side effect of general capability gains.
- **Context and memory management across sessions that exceed practical context-window usage patterns.** Even with a 200K context window, a multi-hour, thousands-of-step agentic session can exhaust or dilute usable context faster than expected (tool outputs, file contents, and intermediate reasoning all consume tokens). The documented emergent use of external memory files is one (partial, tool-availability-dependent) mitigation; more generally this points to summarization, selective context pruning, and external-state offloading as necessary complements to raw context length for long-horizon agents -- an engineering lesson that generalizes well beyond Claude specifically.
- **Reward hacking / specification gaming risk scales with autonomy.** The longer and less supervised an agentic episode is, the more opportunity a capable model has to satisfy a proxy metric (tests pass, code compiles) while violating the actual intent (the bug is genuinely fixed). Anthropic's public emphasis on reducing this behavior in the Claude 4 generation reflects that long-horizon capability gains make previously low-stakes alignment failure modes materially higher-stakes.
- **Safety/security scaffolding around a more capable, more autonomous model.** ASL-3 deployment implies additional infrastructure (enhanced monitoring, more restrictive default tool permissions in some contexts, additional classifiers) layered around inference -- a direct engineering consequence of a capability increase that, per Anthropic's own risk assessment, required more than model-level mitigations alone.

### 9. Inference & Serving Considerations

- Interleaved thinking requires the serving stack to support a request/response loop where thinking, tool_use, tool_result, and further thinking blocks are interleaved within a single logical turn, rather than a strict think-block-then-action-block sequence -- a more complex orchestration contract between client and model than 3.7 Sonnet's simpler "think, then answer" shape.
- Long-horizon autonomous sessions (as in the multi-hour coding case studies) imply serving patterns dominated by many sequential, dependent model calls (often via an agent harness like Claude Code) rather than single isolated requests, which shifts the relevant cost/latency unit from "one response" to "an entire session," with materially different implications for context reuse, prompt caching, and cumulative cost forecasting.
- Thinking-block summarization for sufficiently long traces (see Section 2) means client-side handling of the `thinking` content type must accommodate either a full trace or a summarized trace depending on trace length and model, which is a real integration detail for anyone building on the API across both 3.7 Sonnet and Claude 4 models.
- ASL-3 deployment safeguards for Opus 4 imply the served model sits behind additional operational controls (monitoring, potentially usage restrictions in specific sensitive domains) that are part of the effective "serving system" even though they are not part of the model weights themselves.

### 10. Evaluation, Benchmarks & Known Limitations

Anthropic reported SWE-bench Verified scores for both models in the low-to-mid 70s (percent) under standard single-attempt evaluation, with higher scores (approaching or exceeding 80%) reported under configurations using additional parallel test-time compute/best-of-N sampling strategies -- figures that, as with all agentic coding benchmarks industry-wide, are scaffold- and configuration-dependent and are self-reported by the vendor. Anthropic also highlighted strong results on agentic-tool-use and computer-use-style benchmarks and qualitative case studies (e.g., the multi-hour Rakuten coding session) as evidence for long-horizon reliability specifically, which is inherently harder to reduce to a single leaderboard number than short-horizon benchmark performance.

Known limitations: long-horizon agentic evaluation remains far less standardized than short-horizon benchmarks like SWE-bench Verified, meaning qualitative case studies necessarily carry more weight (and more selection-bias risk) in the public narrative than they would for a metric with broad, independent, adversarial evaluation. Interleaved thinking and tool use also expand the model's effective attack surface for prompt injection and tool-result manipulation (a compromised or adversarial tool result now has a channel into ongoing reasoning, not just into a terminal action), which is a documented general concern for agentic LLM systems and applies here.

### 11. Confirmed Facts vs. Speculation

**Confirmed:**
- Claude Opus 4 and Claude Sonnet 4 launched May 22, 2025, both hybrid-reasoning models served from single model IDs.
- Interleaved thinking with tool use, exposed via a documented beta API header, allowing reasoning to continue across and incorporate tool-call results within one extended-thinking episode.
- Thinking-trace summarization (rather than always-raw display) introduced for sufficiently long Claude 4 thinking blocks, a documented change from Claude 3.7 Sonnet's default behavior.
- Opus 4 was the first Claude model deployed under ASL-3 safeguards per Anthropic's Responsible Scaling Policy.
- Anthropic-published case studies of multi-hour, largely autonomous agentic coding sessions (e.g., with Rakuten).
- Documented emergent use of external memory files by Opus 4 under long-horizon agentic conditions with file-system access.
- Vendor-reported SWE-bench Verified and related agentic benchmark improvements over the Claude 3.x generation.
- General availability expansion of Claude Code alongside this generation.

**Speculation / inference only:**
- Any parameter count, dense-vs-MoE architecture, or layer/attention specifics for Opus 4 or Sonnet 4.
- Specific post-training algorithm(s) used to instill interleaved-thinking behavior or long-horizon reliability (framed above as plausible RL-over-trajectories, not confirmed).
- Data mixture weighting toward code/agentic trajectories.
- Training infrastructure, cluster topology, or precise compute budget for this generation.
- Any precise numeric ceiling on session length, step count, or context reuse strategy underlying the "hours-long autonomy" claims.

### 12. Staff/Research Interview Talking Points

- Be able to explain, precisely, why "long-horizon agentic reliability" is not simply a restatement of "high capability": articulate the distinct sub-problems (error detection/recovery, drift resistance, context/memory management, resistance to reward hacking under low supervision) and be ready to discuss how each might be targeted in training versus mitigated in the serving/harness layer (e.g., Claude Code's scaffolding versus the model's own weights).
- Understand interleaved thinking as a concrete example of "reasoning as a stateful process interacting with an environment" rather than "reasoning as a one-shot cognitive act," and be able to connect this to the broader agent-research framing of interleaving planning and execution (classical AI planning/replanning literature, and contemporary LLM-agent research) rather than treating it as a Claude-specific novelty.
- Be ready to discuss the ASL-3 disclosure as a real, load-bearing example of Anthropic's Responsible Scaling Policy in action -- a concrete case where a capability jump triggered binding process commitments, which is a distinctive and interview-relevant piece of Anthropic's institutional identity versus competitors.
- Be able to articulate the trade-off Anthropic made in moving from raw to summarized thinking traces for longer sequences: this is a direct, disclosed instance of the file-005 transparency debate being revisited under scale/misuse pressure, and a thoughtful answer should treat it as evidence that "transparency" is a tunable design point along a spectrum, not a binary property a model either has or lacks.
- Know the difference between vendor-reported benchmark improvements (SWE-bench Verified deltas) and the harder-to-quantify long-horizon reliability claims (multi-hour case studies), and be prepared to discuss what a more rigorous, standardized long-horizon agentic benchmark would need to measure that current benchmarks largely do not.
