# 008 — Attention Mechanism Birth (Companion Notes)

Companion to `008_attention_mechanism_birth.py`. This file implements Bahdanau-style additive attention (`BahdanauAttention`, `AttentionEncoder`, `AttentionDecoder`, `AttentionSeq2Seq`) and trains it on the same kind of synthetic `reverse` task used in file 007, so the improvement over plain Seq2Seq can be observed directly, including visualizing the learned attention weights as a heatmap.

## Bahdanau (Additive) Attention (Bahdanau, Cho & Bengio, 2015)

### 1. What Problem It Solved

File 007 covered the exact limitation this file exists to fix: in a plain Seq2Seq model, the encoder has to compress an entire input sentence — regardless of length — into one fixed-size context vector, and the decoder only ever sees that single vector. For longer or more information-dense sentences, this is a real bottleneck: important details get squeezed out because the encoder has no way to know in advance which parts of the sentence the decoder will actually need at each step of generation, and it only gets one fixed-size vector to work with regardless.

Bahdanau, Cho, and Bengio's 2015 paper ("Neural Machine Translation by Jointly Learning to Align and Translate") fixed this by removing the "one vector for everything" constraint entirely. Instead of collapsing the encoder's output into a single vector, their model keeps *all* of the encoder's per-position hidden states around, and lets the decoder, at every single output step, compute a fresh weighted combination of them — effectively asking "given what I'm generating right now, which parts of the input sentence should I be looking at?" That per-step, dynamically computed weighted combination is the **attention mechanism**, and the weighted combination itself is called the **context vector** for that step (a different one at every decoding step, unlike Seq2Seq's single, fixed context vector).

### 2. Architecture — How It Works

**Intuition first.** Imagine translating a sentence and, instead of trying to remember the entire source sentence as one blurry mental summary, you keep the whole source sentence visible in front of you and, for every word you write in the translation, you glance back and forth across the source sentence to decide which word(s) are most relevant right now. That glancing-back-and-forth, with a learned sense of "how relevant is each source word to what I'm writing right now," is exactly what attention computes — quantified as a set of attention weights that sum to 1 across the input positions.

**The precise computation**, as implemented in `BahdanauAttention.forward`. At each decoder time step, given the encoder's outputs at every input position (`encoder_outputs`, shape `(batch, input_length, encoder_hidden_dim)`) and the decoder's current hidden state (`decoder_hidden`, shape `(batch, decoder_hidden_dim)`):

```
score_i = attention_vector( tanh( encoder_projection(encoder_outputs_i) + decoder_projection(decoder_hidden) ) )   # for each input position i
attention_weights = softmax(score_1, score_2, ..., score_n)    # masked to ignore padding positions
context_vector = sum_i( attention_weights_i * encoder_outputs_i )
```

This is called **additive attention** because the encoder's projected representation and the decoder's projected representation are *added together* (then passed through `tanh` and a final linear layer to get a single score) — as opposed to being multiplied together, which is what the later Luong-style "dot" and "general" attention variants (file 009) do instead. `encoder_projection` and `decoder_projection` are separate learned linear layers that map the encoder and decoder hidden states into a shared `attention_dim` (128 in this code) so they can be combined even if the encoder and decoder have different hidden sizes.

**A tiny worked example.** Suppose the decoder is generating the 2nd word of the output, and the input sentence had 4 words. The raw (pre-softmax) attention scores computed for the 4 input positions might be, say, `[1.2, 3.5, 0.3, -0.8]`. Softmax turns these into a probability-like distribution: roughly `[0.10, 0.85, 0.03, 0.02]` (the largest raw score dominates after exponentiation and normalization). This means the decoder is putting about 85% of its "attention" on the 2nd input word right now. The context vector for this step is then `0.10 * encoder_output_1 + 0.85 * encoder_output_2 + 0.03 * encoder_output_3 + 0.02 * encoder_output_4` — almost entirely a copy of the encoder's representation of the 2nd input word, with a small blend of the others. At the *next* decoding step, this whole computation runs again from scratch with the decoder's new hidden state, and the attention weights can shift entirely to a different input position. This dynamic re-weighting, recomputed at every step, is precisely what a single fixed context vector could never do.

**Masking padding.** Because sentences in a batch are padded to a common length, the code builds a mask (`mask[i, :length] = 1`) and sets the attention scores at padding positions to a large negative number (`-1e9`) before the softmax, so padding tokens receive essentially zero attention weight rather than competing for probability mass they have no business getting.

**How it plugs into the rest of the model.** `AttentionEncoder` is a **bidirectional** LSTM (`bidirectional=True`, `hidden_dim=256`), producing encoder outputs of size `2 * hidden_dim = 512` at every input position — bidirectional specifically because, as covered in file 005's bidirectional section, an encoder that sees the whole input at once benefits from full left-and-right context, and richer per-position representations give the attention mechanism better material to select from. `AttentionDecoder` computes attention at every step, concatenates the resulting context vector with the current input embedding before feeding it into its own (unidirectional) LSTM, and again concatenates the LSTM's output with the context vector before the final output projection — so the context vector influences both what the decoder "thinks" (its LSTM input) and what it "says" (its output prediction) at every step. Since the bidirectional encoder produces two final hidden states (forward and backward) but the decoder is unidirectional, `AttentionSeq2Seq.forward` combines them by summing (`h[0::2] + h[1::2]`) to initialize the decoder.

### 3. Model Size & Parameters

The original 2015 Bahdanau et al. paper used a bidirectional RNN encoder with 1,000 hidden units (in each direction) and a decoder RNN also with 1,000 hidden units, plus a 620-dimensional word embedding and an alignment (attention) model with a moderately sized hidden layer, evaluated on a vocabulary of 30,000 words per language — all of which is on the order of tens of millions of parameters, a large model for 2015.

This repo's code is a scaled-down version, with: `AttentionEncoder` using `embedding_dim=128`, `hidden_dim=256`, `num_layers=1`, bidirectional (so its output dimension is `2*256=512`); `BahdanauAttention` using `attention_dim=128`; `AttentionDecoder` using `hidden_dim=256`, taking the 512-dimensional encoder output as context; vocabulary capped at 3,000 words. Working through the shapes: the encoder (embedding + bidirectional LSTM) comes to roughly 1.17 million parameters; the attention module itself (three small linear layers projecting into/out of the 128-dimensional attention space) adds a modest ~98,000 parameters; the decoder (embedding + LSTM whose input is embedding+context concatenated, 128+512=640-dimensional + output projection from a 256+512=768-dimensional concatenation to the 3,000-word vocabulary) comes to roughly 3.6 million parameters, dominated by that wide output projection. The full model totals to roughly **4.9 million parameters** — noticeably larger than the plain Seq2Seq model in file 007 (~3.4 million), which makes sense: attention adds its own (small) set of weights, but the much bigger contributor is that bidirectionality doubles the encoder's recurrent cost and the wider concatenated vectors (context + hidden state) make the decoder's input and output layers larger too.

### 4. Dataset & What It Was Trained On

The original paper trained and evaluated on the WMT'14 English-to-French translation task (the same benchmark used by the Sutskever et al. Seq2Seq paper), and specifically highlighted that their attention-based model held up much better on long sentences than a plain encoder-decoder baseline — the exact failure mode attention was designed to fix.

This code again uses **WikiText-2** sentences (filtered to 6-25 tokens, slightly longer than file 007's 5-20 token range, specifically chosen to be long enough that attention's benefit has room to show up), with the same `reverse` synthetic task as file 007. Only small subsets are used: 1,500 training sentences, 300 validation, 300 test, vocabulary capped at 3,000 words. As with the other files in this series, WikiText-2 plus a synthetic task is used in place of a real parallel translation corpus, trading realism for a fast, reproducible, and easy-to-inspect demonstration of the mechanism itself.

### 5. Training Process

**Objective and optimization.** Same structure as file 007: `nn.CrossEntropyLoss(ignore_index=0)` to ignore padding, Adam optimizer at learning rate `0.001`, batch size 32, trained for 12 epochs, gradient clipping at norm `1.0`, teacher forcing at a 50% ratio per decoding step during training (0% during evaluation/generation, matching the same teacher-forcing setup described in file 007).

**What's different from file 007's training loop** is entirely inside the model's forward pass, not the outer training procedure: at each decoding step, the model now additionally computes attention weights over all encoder positions before producing its output, and this attention computation participates fully in backpropagation — the gradient flows back not just through the decoder's LSTM and embeddings, but through the attention scoring network (`encoder_projection`, `decoder_projection`, `attention_vector`) as well. This means the network is learning, end-to-end and purely from the translation-style loss (no explicit alignment supervision), *which* input positions matter for each output position — the alignment itself is learned, not hand-specified.

**Historical note.** The original paper trained with Adadelta (an adaptive learning rate method that predates Adam's widespread adoption) and used minibatches of 80 sentences, on a much larger real parallel corpus, for a genuinely long training run on a single GPU (multiple days) — this file's Adam optimizer and 12 epochs on a few hundred sentences is a fast approximation of the same underlying training procedure, not a faithful reproduction of scale.

### 6. Training Challenges

The core new challenge attention introduces (beyond everything already inherited from LSTM/Seq2Seq — vanishing gradients, exposure bias, and so on) is that the model must learn **alignment** — which input positions correspond to which output positions — with no direct supervision telling it the correct alignment. It only ever gets a gradient signal from "did the final predicted word match the target," and has to work backward from that to figure out where in the input it should have been looking. Early in training, attention weights tend to be close to uniform (roughly equal weight everywhere, since the attention scoring network starts with essentially random weights) — a meaningfully "peaked" and correct alignment pattern is something the model has to learn over the course of training, and it can take longer to emerge than a well-fitted loss curve alone might suggest.

A second, more computational challenge is that attention is not free: computing attention scores over all encoder positions at every single decoding step means the total attention computation scales with `input_length x output_length`, compared to plain Seq2Seq's constant per-step cost (just reading the one fixed context vector). For short sequences (as used in this file's demo) this overhead is negligible; it becomes a real scaling concern for long documents, which is part of what later motivated more efficient attention variants (a topic the broader Transformers-era literature — not this repo's files — eventually addresses with techniques like sparse or linear attention).

A third challenge, specific to this implementation, is correctly reconciling the bidirectional encoder with the unidirectional decoder: the code's choice to *sum* the forward and backward final hidden/cell states (rather than, say, concatenating and projecting them) is a deliberate simplification that avoids adding an extra learned projection layer, at the cost of losing the ability to weight forward vs. backward context differently when forming the decoder's initial state.

### 7. Performance & Evaluation

This file evaluates using validation cross-entropy loss, matching file 007's evaluation approach. Beyond the loss number itself, the code's real evaluation tool is qualitative: `visualize_attention` renders the attention weight matrix as a heatmap (output positions on one axis, input positions on the other), which lets you visually check whether the model has learned a sensible alignment — for the `reverse` task specifically, a well-trained model's attention heatmap should show a roughly anti-diagonal pattern (the decoder's 1st output should attend most strongly to the encoder's *last* input position, the 2nd output to the second-to-last, and so on), which is a directly interpretable, visual confirmation that the mechanism is doing what it's supposed to.

Historically, the Bahdanau et al. 2015 model achieved translation quality competitive with (and, on longer sentences, clearly better than) the non-attention Seq2Seq baseline of the time, and the paper's own analysis explicitly showed that a plain encoder-decoder's BLEU score degraded sharply as sentence length increased, while the attention-based model's performance stayed far more stable across sentence lengths — direct empirical evidence that attention specifically fixes the long-sequence weakness caused by the fixed context vector bottleneck.

### 8. Impact — Why It Mattered

This is one of the most consequential ideas in the whole history of modern NLP. Attention solved the Seq2Seq bottleneck, gave models a form of built-in interpretability (you can literally look at what the model is "looking at"), and — most importantly for everything that came after — introduced the general pattern of computing a learned, dynamic weighting over a set of vectors based on a query. That exact pattern, generalized and refined, is the entire basis of every subsequent development in this series: Luong (2015, file 009) simplified and varied how the attention *score* is computed; self-attention (2016-2017, file 010) generalized attention to relate a sequence to *itself* rather than only linking a decoder to an encoder; and the Transformer (2017, "Attention Is All You Need," beyond this file's scope but the direct destination of this whole arc) removed recurrence entirely and built a full architecture purely out of (self-)attention layers. Every one of those steps is a variation on the mechanism first introduced here.

### 9. How To Explain This In An Interview

"Plain Seq2Seq has a hard architectural bottleneck: the entire input sentence gets compressed into one fixed-size context vector, and the decoder only ever sees that one vector, so information gets lost, especially on longer sentences. Bahdanau attention removes that bottleneck by keeping all of the encoder's per-position outputs around and letting the decoder compute a fresh, learned weighted combination of them at every single decoding step — effectively asking 'given what I'm generating right now, which input words matter most?' Concretely, I implemented additive attention: project both the encoder outputs and the current decoder hidden state into a shared space, add them, pass through tanh and a linear layer to get a score per input position, mask out padding, and softmax those scores into attention weights that sum to one. The weighted sum of encoder outputs using those weights is the context vector for that step, and it's different every step, unlike Seq2Seq's single static context vector. I paired this with a bidirectional LSTM encoder, since giving the encoder full left-and-right context per position gives attention richer material to select from, and I combined the encoder's forward and backward final states by summing them to initialize the unidirectional decoder. I trained it end-to-end on a synthetic reverse task with cross-entropy loss and teacher forcing, with no direct supervision on what the correct alignment should be — the model has to learn which input positions matter purely from whether its final predictions are correct, and I verified it learned something sensible by visualizing the attention weights as a heatmap, which for the reverse task shows a clear diagonal-flipped alignment pattern. This mechanism directly generalizes into everything that follows in NLP history: Luong's simplified scoring variants, self-attention relating a sequence to itself, and ultimately the Transformer, which is built entirely out of this same query-based weighted-combination idea with recurrence removed altogether."
