# 010 — Advanced Attention Mechanisms (Companion Notes)

Companion to `010_advanced_attention_mechanisms.py`. This file implements the building blocks that directly precede the Transformer: scaled dot-product attention, multi-head attention, sinusoidal positional encoding, and a full self-attention encoder layer (attention + feed-forward + residual connections + layer normalization), assembled into both a sequence classifier and a causal (autoregressive) self-attention language model — with no recurrence anywhere in either model.

## Self-Attention & Multi-Head Attention (2016-2017 pre-Transformer building blocks)

### 1. What Problem It Solved

Every attention mechanism covered so far in this series — Bahdanau (file 008) and Luong (file 009) — has the same shape: a **decoder** position attends over **encoder** positions. Attention, in other words, was still bolted onto an RNN/LSTM-based encoder-decoder architecture; it changed *how* the decoder accessed the encoder's information, but recurrence was still doing the heavy lifting of actually processing the sequence, one token at a time, in both the encoder and the decoder. That meant two limitations remained even after attention: (1) recurrence is inherently sequential — you cannot compute the hidden state at position 10 before you've computed positions 1 through 9, which caps how much you can parallelize training on modern hardware (GPUs excel at doing many independent computations at once, and a strictly sequential recurrence fights against that); and (2) relating two *distant positions within the same sequence* (not decoder-to-encoder, but position 3 to position 47 of the same sentence) still had to happen indirectly, by information slowly propagating step by step through the recurrence, which is exactly the same kind of long-range dependency problem that originally motivated LSTM/GRU.

**Self-attention** answers both problems by generalizing the attention mechanism so that a sequence attends *to itself*: every position computes attention scores against every other position in the same sequence, with no recurrence involved. Because there is no step-by-step dependency, every position's attention computation can be done in parallel, and because every position can directly score its relevance to every other position, a dependency between token 3 and token 47 is now a single computation step, not the result of information trickling through 44 sequential updates.

### 2. Architecture — How It Works

**Intuition first.** In Bahdanau/Luong attention, the query ("what am I trying to generate right now") came from the decoder, and the keys/values ("what information is available") came from the encoder — two different sequences. In self-attention, the query, keys, and values all come from the *same* sequence: every word asks "which other words in this same sentence are relevant to understanding me?" and gets to look at every other word (including itself) to answer that.

**Scaled dot-product attention — the precise computation.** This is the core operation, implemented in `ScaledDotProductAttention.forward`:

```
Attention(Q, K, V) = softmax( Q K^T / sqrt(d_k) ) V
```

`Q` (query), `K` (key), and `V` (value) are all linear projections of the input sequence. `Q K^T` computes a dot-product similarity score between every query position and every key position at once (this is Luong's "dot" scoring function from file 009, generalized from "one decoder position vs. many encoder positions" to "every position vs. every position"). The result is divided by `sqrt(d_k)` (the square root of the per-head dimension) before the softmax — this scaling matters: as the dimension `d_k` grows, the dot products between random vectors tend to grow in magnitude too, which would push the softmax into a very sharp, saturated regime (one position getting almost all the weight, gradients vanishing everywhere else) — dividing by `sqrt(d_k)` keeps the scores in a numerically reasonable range regardless of dimension.

**A tiny worked example.** Take a toy case with `d_k = 4` and suppose a query vector dotted with a particular key vector gives a raw score of `8`. Without scaling, `softmax` over scores like `[8, 1, 0.5]` would produce something very close to `[0.999, 0.0009, 0.0005]` — the model has essentially made a hard, all-or-nothing choice, and gradients for the other positions are nearly zero, making it hard to learn anything about them. Dividing by `sqrt(4) = 2` first gives scores `[4, 0.5, 0.25]`, and `softmax` over these produces a noticeably softer distribution, something like `[0.94, 0.03, 0.02]` — still clearly favoring the first position, but not so extremely that the model has zero learning signal for the alternatives. This scaling is exactly what keeps large-dimensional attention trainable.

**Multi-head attention.** A single attention computation forces the model to squeeze *all* kinds of relationships (syntactic, semantic, positional, whatever the task needs) through one shared query/key/value projection. `MultiHeadAttention` instead splits the model dimension into several smaller, independent "heads" — in this code, `d_model=256` split into `num_heads=8` heads of `d_k = 256/8 = 32` each — and computes scaled dot-product attention separately within each head, using its own independently learned Q/K/V projections:

```
head_i = Attention(Q W_q_i, K W_k_i, V W_v_i)     # each head attends independently, in its own 32-dim subspace
output  = Concat(head_1, ..., head_8) W_o          # concatenate all heads, then one final learned projection
```

Each head is free to specialize — one head might learn to track "which word does this pronoun refer to," another might track "what's the subject of this verb" — and because they operate on different, independent lower-dimensional projections of the same input, they can capture different kinds of relationships simultaneously rather than being forced to average them all into one representation.

**Positional encoding.** Self-attention, unlike an RNN, has no built-in sense of word order at all — dot products between Q and K don't care whether a word came first or last, only what its content vector looks like. Without some fix, self-attention would treat a sentence as an unordered "bag" of tokens. `PositionalEncoding` fixes this by adding a deterministic, position-dependent pattern directly to each token's embedding before it enters the attention layers:

```
PE(pos, 2i)   = sin(pos / 10000^(2i/d_model))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))
```

Each position gets a unique combination of sine/cosine values across the embedding dimensions, at different frequencies — low dimensions oscillate quickly across positions, high dimensions oscillate slowly — so nearby positions get similar (but not identical) encodings, and the model can learn to infer relative position from these patterns. This encoding is fixed (not learned) and simply added to the embedding, so the same word at a different position in the sentence ends up with a slightly different vector, breaking the "bag of tokens" symmetry.

**Assembling a full self-attention encoder layer.** `SelfAttentionEncoderLayer` combines multi-head self-attention with a position-wise feed-forward network, using residual ("skip") connections and layer normalization around each:

```
x = LayerNorm(x + MultiHeadAttention(x, x, x))     # self-attention sub-layer, with residual connection
x = LayerNorm(x + FeedForward(x))                   # feed-forward sub-layer, with residual connection
```

The residual connections give gradients a direct path around each sub-layer (echoing, in spirit, the same "give gradients a shortcut" idea behind LSTM's cell state, though the mechanism is architecturally different), and layer normalization keeps activations at a stable scale as they pass through several stacked layers — this code stacks 3 of these layers (`num_layers=3`).

**Two use cases built on the same blocks.** `SelfAttentionClassifier` stacks these layers, adds positional encoding, and pools the final representations (masked average across valid positions) into a classification head — every position can freely attend to every other position, with no restrictions, since the whole input is available at once (this is sometimes called "encoder-style," bidirectional-equivalent self-attention). `SelfAttentionLanguageModel` uses the identical stack of layers but applies a **causal mask** (`create_causal_mask`, a lower-triangular matrix of 1s) before the softmax in every attention layer, which forces each position to only attend to itself and *earlier* positions — this is what makes it usable for autoregressive next-word prediction without "cheating" by looking at future tokens, the self-attention equivalent of why a decoder can't be bidirectional (see file 005's Bidirectional LSTM section for the same constraint in a recurrent context).

### 3. Model Size & Parameters

The building blocks in this file predate and directly feed into the Transformer, formalized in "Attention Is All You Need" (Vaswani et al., 2017), whose base model used `d_model=512`, 8 attention heads, 6 stacked encoder layers and 6 decoder layers, and a feed-forward dimension of 2048, totaling around 65 million parameters — already large for 2017, and dwarfed by what came after (GPT, BERT, and beyond).

This repo's code uses `d_model=256`, `num_heads=8` (so `d_k=32` per head), `num_layers=3`, `d_ff=512`, vocabulary capped at 3,000 words — roughly half the width and half the depth of the original Transformer's base configuration. Working through the shapes: each self-attention layer costs about 527,000 parameters (the four `256x256` projection matrices inside multi-head attention — `W_q`, `W_k`, `W_v`, `W_o` — contribute about 263,000, and the two-layer feed-forward network, `256->512->256`, contributes about 263,000, plus two small `LayerNorm` layers); stacking 3 of these layers costs about 1.58 million parameters total. The `SelfAttentionClassifier` adds a small classification head (~33,000 parameters) on top of the embedding (~384,000) and layer stack, for a total of roughly **2.0 million parameters**. The `SelfAttentionLanguageModel` instead adds a full output projection back to the 3,000-word vocabulary (~771,000 parameters) on top of the same embedding and layer stack, totaling roughly **2.7 million parameters**. Both are comparable in scale to the LSTM and GRU models earlier in this series (2.1M and 1.85M respectively), which is a deliberate design choice in this repo — it lets you compare a self-attention model against a recurrent model of similar overall size, rather than confounding "self-attention is better" with "self-attention model happened to be bigger."

### 4. Dataset & What It Was Trained On

The concepts in this file (scaled dot-product attention, multi-head attention) were formalized and popularized in the 2017 Transformer paper, trained on the WMT'14 English-German and English-French translation datasets — the same family of large parallel translation corpora used by the Seq2Seq and attention papers earlier in this series. The self-attention *building blocks* themselves, though, are general-purpose — they underpin not just translation but classification, language modeling, and (as this file demonstrates with two different task setups) essentially any sequence task.

This code uses **WikiText-2** sentences filtered to 8-30 tokens (the longest range used anywhere in this series so far, chosen because self-attention's advantage — direct long-range connections — is most visible on longer sequences), with only 1,000 training sentences, 200 validation, 200 test, and a 3,000-word vocabulary. Two synthetic tasks are constructed from this data: a **sequence classification** task (labeling a sentence as "long" or "short" using a simple length-based heuristic — sentences longer than 15 tokens get label 1, otherwise label 0 — a synthetic proxy task, not a real semantic classification problem, chosen purely so the classifier architecture has something concrete to learn) and a **language modeling** task (standard next-word prediction, same setup as files 004-006, but with a self-attention model instead of an RNN/LSTM/GRU). The code also defines (but does not exercise in `main()`) a masked-language-modeling dataset variant (`masked_lm`, BERT-style 15% token masking), present as an illustration of the concept but not run in this file's demonstration.

### 5. Training Process

**Classification model.** Trained with `nn.CrossEntropyLoss` (no `ignore_index`, since classification labels aren't padded — only the *inputs* are padded, and the model's masked-average-pooling step explicitly excludes padding positions rather than relying on the loss function to ignore anything), Adam optimizer at learning rate `0.001`, batch size 32, 8 epochs, gradient clipping at norm `1.0`. Note there is no teacher forcing here at all — that concept doesn't apply once you're not autoregressively generating a sequence; classification just needs one forward pass and one label per sequence.

**Language model.** Trained with `nn.CrossEntropyLoss(ignore_index=0)` (padding-aware, matching the recurrent language models in files 004-006), same Adam/batch size/epoch/clipping settings, with the causal mask applied inside every attention layer so the model genuinely cannot see future tokens during training — this is what makes its training procedure valid for autoregressive generation later, even though, unlike an RNN, the entire sequence's loss can be computed in a single parallel forward pass (rather than one sequential step at a time), because the causal mask enforces the "no peeking at the future" constraint structurally rather than through sequential processing order.

**Historical note.** The original Transformer paper trained with Adam using a specific learning-rate warmup-then-decay schedule (rather than this file's constant learning rate), label smoothing on the loss, and considerably larger batches (in tokens, not just sequences) distributed across multiple GPUs, over roughly 12 hours (base model) to 3.5 days (big model) — again, a difference of scale and training-schedule sophistication, not of the underlying mechanism, which this file implements faithfully.

### 6. Training Challenges

The challenge that no longer applies here, and is worth calling out explicitly because it's the whole point of this architecture: **there is no vanishing gradient problem caused by sequential depth**, because there's no recurrence — gradients don't have to flow backward through 50 or 100 sequential time steps the way they did for the RNN in file 004. Depth still exists (3 stacked self-attention layers here), but it's a fixed, small number of layers, and each layer has direct residual connections specifically to keep gradients flowing well through *that* kind of depth (analogous to, but architecturally distinct from, why LSTM's cell state helps gradients flow through *recurrent* depth).

The challenges that remain, or are new here, are different in kind. **Positional information has to be explicitly re-added**, because self-attention is inherently permutation-invariant (it would treat "the dog bit the man" and "the man bit the dog" identically without positional encoding, since both contain the same set of tokens) — get this wrong or omit it, and the model structurally cannot learn word-order-dependent meaning. **Multi-head attention has more hyperparameters to get right** — the number of heads and the resulting per-head dimension (`d_model` must divide evenly by `num_heads`, enforced by an `assert` in this code) trade off between giving each head more room to represent complex relationships (fewer heads, larger `d_k`) versus letting the model capture more distinct types of relationships simultaneously (more heads, smaller `d_k`). And **causal masking has to be implemented correctly** for the language model variant — a bug here (for example, forgetting to mask, or masking in the wrong direction) would let the model "see" the answer it's supposed to predict, producing deceptively excellent training loss that collapses at real generation time, when future tokens genuinely don't exist yet.

### 7. Performance & Evaluation

The classification model is evaluated with **accuracy** (fraction of validation sentences correctly labeled long/short) — a plain, category-level metric appropriate for a classification task. The language model is evaluated with **perplexity** (`exp` of average cross-entropy loss), consistent with every other language model in this series (files 004-006), which makes it directly comparable in kind (though not in absolute number, given the different dataset subsets and vocabulary draws) to the RNN/LSTM/GRU perplexities elsewhere in this repo. The code additionally visualizes attention weights per layer and per head as heatmaps (`visualize_self_attention`), which is where multi-head attention's promise of "different heads learn different relationships" becomes directly inspectable — different heads, visualized side by side for the same sentence, can show visibly different attention patterns (one head might attend locally to nearby words, another might jump to a specific distant word).

Historically, once assembled into the full Transformer (beyond this file's scope, but its direct successor), these exact building blocks — scaled dot-product attention, multi-head attention, positional encoding, residual+LayerNorm blocks — achieved a new state of the art in machine translation quality (28.4 BLEU on WMT'14 English-German, 41.8 on English-French for the "big" Transformer model) while training significantly faster than the best previous recurrent or convolutional models, precisely because removing recurrence allowed full parallelization across the sequence dimension during training.

### 8. Impact — Why It Mattered

This file's building blocks are, quite directly, the immediate predecessor of the Transformer architecture that reshaped essentially all of modern NLP (and much of deep learning more broadly). Everything demonstrated here — self-attention replacing recurrence, multiple heads capturing different relationship types, sinusoidal positional encoding compensating for attention's lack of inherent order-awareness, residual connections and layer normalization stabilizing training through stacked layers — appears essentially unchanged inside the actual Transformer encoder (and, with the addition of causal masking exactly as implemented here, the Transformer decoder too). The core promise that made this worth pursuing — full parallelization during training, direct (not step-by-step) connections between any two positions regardless of distance — is precisely what let subsequent models scale up dramatically in size and training data, which is the story of everything from BERT (2018, a bidirectional self-attention encoder much like this file's classifier, trained with masked language modeling) through GPT (a causal self-attention language model much like this file's language model, scaled up enormously) and onward. In the arc of this entire series, this file is the hinge point: everything before it (RNN, LSTM, GRU, Seq2Seq, Bahdanau, Luong) is the recurrent, attention-assisted lineage; everything historically after it is the self-attention-only, recurrence-free lineage that current large language models descend from.

### 9. How To Explain This In An Interview

"Bahdanau and Luong attention improved how a decoder accesses an encoder's information, but the encoder and decoder were still RNNs under the hood, which meant two limitations remained: sequential processing that can't be parallelized, and long-range dependencies within a single sequence that still had to propagate step by step. Self-attention generalizes attention so a sequence attends to itself directly — every position computes a query, key, and value, and scores its relevance to every other position in one shot using scaled dot-product attention, `softmax(QK^T / sqrt(d_k))V`, where the scaling by `sqrt(d_k)` keeps the softmax from saturating as the dimension grows. I implemented multi-head attention on top of that — splitting the model dimension into several smaller subspaces, in my case 8 heads of 32 dimensions each, so different heads can specialize in different kinds of relationships instead of averaging everything into one representation. Because self-attention has no inherent notion of order, I added sinusoidal positional encoding directly to the embeddings so the model can tell position 1 from position 10. I assembled these into a full self-attention encoder layer with residual connections and layer normalization around both the attention and the feed-forward sub-layers, stacked three of them, and used the exact same stack for two different tasks: a bidirectional-style sequence classifier, and a causal, autoregressive language model, where the only difference is a triangular mask that stops each position from attending to future positions — which is the self-attention equivalent of why a decoder can't be bidirectional. The big practical win over everything earlier in this series is that there's no vanishing gradient problem from sequential depth anymore, and training is fully parallelizable across the sequence, which is exactly what let this style of model scale up into the Transformer, and from there into BERT and GPT."
