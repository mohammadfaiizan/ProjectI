# 009 — Luong Attention Variants (Companion Notes)

Companion to `009_luong_attention_variants.py`. This file implements the family of attention scoring functions introduced by Luong, Pham, and Manning (2015) — dot, general, and concat — plus a local (windowed) attention variant, and an input-feeding decoder, and trains two of them (`dot` and `general`, per the code's own `main()`, which explicitly trains only the first two of the four defined variants "for demo") on the same synthetic `reverse` task used in files 007 and 008.

## Luong Attention (Luong, Pham & Manning, 2015)

### 1. What Problem It Solved

Bahdanau attention (file 008) proved that letting a decoder dynamically attend over all encoder positions fixes the fixed-context-vector bottleneck of plain Seq2Seq. But it did so with one specific, somewhat expensive scoring function: project the encoder state and decoder state separately, add them, pass through `tanh`, then through another learned vector to get a single score. That's a full extra feedforward network computed at every input position, at every decoding step.

Luong, Pham, and Manning (2015) asked a narrower, more practical question: does attention *need* to be computed that way, or can simpler (and cheaper) scoring functions work just as well? Their paper introduced several alternative ways to compute the same kind of attention score, ranging from a plain dot product (almost free to compute) up to something structurally similar to Bahdanau's. They also introduced **local attention** — restricting attention to a small window of positions instead of the entire input — and an **input-feeding** approach that gives the decoder access to its own previous attention decision when making its next one. Together, these were aimed at making attention faster and, in some configurations, more effective, without giving up the core benefit that Bahdanau established.

### 2. Architecture — How It Works

**Intuition first.** All of Luong's variants answer the exact same question as Bahdanau's attention — "how relevant is each encoder position to what the decoder is doing right now?" — they just differ in *how directly* they compare the decoder's current state to each encoder position. Dot product asks "how aligned are these two vectors, literally, with no extra learned transformation?" General attention asks the same question but first passes the encoder vector through a learned transformation, so the model can learn what "alignment" should mean rather than using raw geometric similarity. Concat attention is structurally closest to Bahdanau's approach: combine the two vectors and learn a scoring function on top of the combination.

**The precise computation**, as implemented in `LuongAttention.forward`, for a decoder hidden state `h_t` (shape `(batch, hidden_dim)`) and encoder outputs `h_s` at every input position (shape `(batch, seq_len, hidden_dim)`):

```
Dot:     score(h_t, h_s) = h_t^T · h_s                          # raw dot product, no learned weights
General: score(h_t, h_s) = h_t^T · W_a · h_s                    # h_s first passed through learned W_a
Concat:  score(h_t, h_s) = v_a^T · tanh(W_a · [h_t ; h_s])       # concatenate, transform, then score (closest to Bahdanau)
```

In all three cases, once the scores for every input position are computed, the rest is identical to Bahdanau: mask out padding positions, `softmax` the scores into attention weights, and take the weighted sum of encoder outputs as the context vector.

**A tiny worked example, comparing dot vs. general.** Suppose (for a toy 3-dimensional hidden state) the decoder's current hidden state is `h_t = [1, 0, 1]` and one encoder position's output is `h_s = [1, 1, 0]`. The **dot** score is simply `h_t · h_s = (1*1) + (0*1) + (1*0) = 1`. Now suppose the **general** attention's learned matrix `W_a` happens to scale the third dimension up a lot (say it maps `h_s` to `[1, 1, 3]` after the transformation) — then the general score becomes `h_t · [1,1,3] = 1 + 0 + 3 = 4`. Both variants are answering "how relevant is this position," but general attention can *learn* to emphasize dimensions of the encoder representation that turn out to matter for alignment, even if they don't dominate a raw dot product — this extra flexibility is exactly what the single learned matrix `W_a` buys over plain dot product, at the cost of `hidden_dim x hidden_dim` extra parameters.

**Global vs. local attention.** Everything described above — attending over *every* encoder position — is what Luong calls **global attention**, and it's what `LuongAttention` implements. `LocalAttention` implements the alternative: rather than scoring every position, it first predicts a single "center" position to focus on (`position_network`, a linear layer mapping the decoder hidden state to one number, passed through a sigmoid and scaled up to the sequence length), then computes attention scores only for a small window of positions around that predicted center (`window_size=5` in this code, so 2 positions on each side of the center). This is a simplified version of what Luong's paper calls "local-p" (predictive) attention. The motivation is efficiency: for very long input sequences, computing a full score over every position at every decoding step is wasteful if the relevant context is usually localized anyway.

**Input feeding.** `LuongDecoder` implements a detail that's easy to miss but is one of Luong's real contributions: at each decoding step, the *previous* step's attention context vector is concatenated with the current input embedding before being fed into the LSTM (`lstm_input = concat(embedded, prev_context)`), rather than only being used afterward (as Bahdanau's decoder does — Bahdanau uses the *current* step's context after computing it, whereas Luong's input-feeding explicitly carries the *previous* step's attention decision forward as part of the next step's input). The intuition is that this lets the decoder's recurrent state "know" what it already attended to last time, which can help it avoid attending to the same information repeatedly or losing track of what's already been covered — genuinely useful for tasks like translation where you generally don't want to translate the same source word twice.

### 3. Model Size & Parameters

The original 2015 Luong et al. paper used stacked LSTMs with 1,000 hidden units per layer (4 layers deep) and a 1,000-dimensional embedding, evaluated on a 50,000-word vocabulary for English-German translation — broadly comparable in scale to the Bahdanau paper, on the order of tens of millions of parameters.

This repo's code uses much smaller dimensions, matched across variants for fair comparison: `LuongEncoder` and `LuongDecoder` both use `embedding_dim=128`, `hidden_dim=256`, `num_layers=1` (unidirectional, unlike file 008's bidirectional encoder — a deliberate simplification here), vocabulary capped at 3,000 words. The parameter cost of the *scoring function itself* differs meaningfully between variants, which is worth being precise about: **dot** attention adds zero extra learned parameters (it's a pure operation on existing vectors); **general** attention adds one `hidden_dim x hidden_dim` matrix, about 65,500 parameters at `hidden_dim=256`; **concat** attention adds a larger `(2*hidden_dim) x hidden_dim` matrix plus a small scoring vector, about 131,300 parameters. Putting a full model together (using the `general` variant as a representative example): the encoder (embedding + 1-layer LSTM) costs roughly 779,000 parameters; the attention module adds about 65,500; the input-feeding decoder (embedding + LSTM whose input is embedding+previous-context, `128+256=384`-dimensional + an output projection from the concatenated `2*256=512`-dimensional hidden+context vector to the 3,000-word vocabulary) costs roughly 2.58 million parameters, again dominated by that wide output layer. The full model totals to roughly **3.4 million parameters** for the `general` variant — smaller than file 008's bidirectional Bahdanau model (~4.9 million), mostly because this file's encoder is unidirectional rather than bidirectional, which is a bigger driver of the size difference than the choice of scoring function itself.

### 4. Dataset & What It Was Trained On

The original paper was trained and evaluated on the WMT English-German translation task, and specifically reported that their local attention with the general scoring function outperformed several other combinations, establishing "general" attention with input feeding as a particularly strong, and notably simpler-to-compute, configuration relative to Bahdanau's original design.

This code, consistent with the rest of the series, substitutes **WikiText-2** sentences (filtered to 6-25 tokens) and the same `reverse` synthetic task used in files 007 and 008. It also defines (but does not use, in `main()`) a `translation` task that does simple word-for-word French substitution on a handful of common English words (`the -> le`, `a -> un`, `is -> est`, and so on) — this is present in the dataset class as an illustration of what a toy translation task might look like, but the actual training run in this file's `main()` only exercises the `reverse` task. Training subsets are small: 1,200 sentences for training, 240 for validation, 240 for test, vocabulary capped at 3,000 words.

### 5. Training Process

**Objective and optimization.** Consistent with files 007-008: `nn.CrossEntropyLoss(ignore_index=0)`, Adam at learning rate `0.001`, batch size 32, gradient clipping at norm `1.0`, teacher forcing at 50% per decoding step. The code's `train_model` function defaults to 12 epochs, but `main()` explicitly calls it with 10 epochs for the demonstration run.

**What the code actually trains.** `main()` defines four attention configurations — `dot`, `general`, `concat`, and `general`-with-local-attention — but then explicitly slices to only the first two (`attention_variants[:2]`, i.e. `dot` and `general`) when running the training loop, commented in the code as "Test first 2 for demo," presumably to keep the total demonstration runtime reasonable. The `concat` and local-attention variants are fully implemented and available to run, just not exercised by the default `main()` execution — worth knowing precisely if you're describing "what this code actually does" versus "what capability this code has."

**Historical note.** As with the earlier attention paper, Luong et al.'s original training used a period-appropriate optimizer (plain SGD with a decaying learning rate schedule) and much larger real parallel corpora over a multi-day training run — this file's Adam-based, few-hundred-sentence training run trades faithfulness to the original scale for speed and easy inspection.

### 6. Training Challenges

All the challenges already discussed for Bahdanau attention (file 008) — learning alignment with no direct supervision, the added per-step computational cost, exposure bias mitigated by teacher forcing — apply here equally, since the underlying learning problem is the same.

Two challenges are specific to this file's additional mechanisms. First, **local attention's position prediction** (`position_network`) introduces a genuinely harder optimization problem: the model must learn to predict *where* to look (a continuous position estimate) at the same time as learning *what* to do with what it finds there, and if the position prediction is initially poor, the windowed attention scores computed around a bad guess will be scored over the wrong part of the input entirely — a bootstrapping problem that global attention doesn't have, since global attention always considers every position and lets the softmax sort out relevance. Second, **input feeding** slightly complicates the very first decoding step, since there is no "previous context" yet — the code handles this by explicitly feeding a zero vector as the placeholder context for the first step, which is a reasonable but noticeable special case in the architecture.

### 7. Performance & Evaluation

This file evaluates with validation cross-entropy loss, consistent with files 007-008, and additionally builds a side-by-side visual comparison of attention weight heatmaps across the different scoring mechanisms actually trained (`compare_attention_mechanisms`), letting you inspect whether `dot` and `general` attention converge on similar or different alignment patterns for the same input sentence.

Historically, Luong et al.'s own evaluation (BLEU score on WMT English-German) found that their best single-model configuration (local attention with the general scoring function, combined with input feeding) outperformed the Bahdanau-style baseline of the time, while also being simpler and computationally cheaper per step for the dot and general variants specifically — the paper's central claim was that you don't need the full additive scoring machinery to get strong attention-based translation results.

### 8. Impact — Why It Mattered

Luong's contribution was less about a new capability and more about simplification and practical refinement: showing which parts of the original attention formulation were essential (dynamically weighting encoder positions based on decoder state) and which were incidental design choices (the specific additive scoring function). The **dot-product** scoring function in particular — "how aligned are these two vectors, computed via a raw dot product" — turns out to be a direct conceptual ancestor of the **scaled dot-product attention** used in self-attention and the Transformer (file 010 and beyond): the Transformer's `Attention(Q, K, V) = softmax(QK^T / sqrt(d_k))V` is, at its core, exactly Luong's dot-product scoring function, generalized to compare many positions to many positions simultaneously (instead of one decoder position to many encoder positions) and normalized by a scaling factor for numerical stability. Input feeding's idea — letting the model's attention history influence its future decisions — echoes forward conceptually into how later architectures track what's already been "used." In the arc of this series, Luong attention is the bridge between Bahdanau's proof-of-concept and the fully generalized, matrix-multiplication-based attention that self-attention and the Transformer build on.

### 9. How To Explain This In An Interview

"Bahdanau attention proved dynamic attention over encoder positions fixes the Seq2Seq bottleneck, but its scoring function — project both sides, add them, tanh, then score — is relatively expensive. Luong's 2015 paper asked whether simpler scoring functions could work just as well, and proposed three: dot product, which just takes the raw dot product of the decoder and encoder vectors with no extra learned weights; general, which adds one learned matrix so the model can learn what 'alignment' should mean rather than relying on raw vector similarity; and concat, which is structurally closest to Bahdanau's original approach. I implemented all three, plus a local attention variant that predicts a single focus position and only scores a small window around it instead of the whole sequence, and an input-feeding decoder that carries the previous step's attention context forward into the next step's input, so the decoder has some memory of what it already attended to. I trained the dot and general variants side by side on a synthetic reverse task with the same optimizer, loss, and teacher-forcing setup as the Bahdanau file, so the comparison would be apples-to-apples, and I visualized the resulting attention heatmaps to compare how the different scoring functions align. The historically important thread here is that Luong's dot-product scoring function is a direct conceptual ancestor of the scaled dot-product attention used in the Transformer — the core operation, softmax over a similarity score between vectors, is the same; what changes later is generalizing it from 'one decoder position looking at many encoder positions' to 'every position looking at every other position,' which is exactly what self-attention does next."
