# Time Series And Econometrics Interview

## Q1: What's the difference between strict stationarity and weak stationarity?

**A1:** Strict stationarity requires that the joint distribution of (X_{t₁}, ..., X_{tₖ}) is the same as (X_{t₁+τ}, ..., X_{tₖ+τ}) for any shift τ and any k. This means all moments and dependencies are time-invariant. Weak stationarity (also covariance stationarity) only requires: (1) E[X_t] = μ (constant mean), (2) Var(X_t) = σ² (constant variance), (3) Cov(X_t, X_{t+h}) depends only on lag h, not on t. Weak stationarity is easier to verify and is sufficient for most time series methods (ARIMA, GARCH). Strict stationarity implies weak stationarity if second moments exist, but not vice versa. In finance, weak stationarity is often assumed for returns (constant mean and variance), though volatility clustering suggests this may not hold. Many models (GARCH) assume weak stationarity while allowing conditional heteroskedasticity.

## Q2: Explain unit root testing using the Augmented Dickey-Fuller (ADF) test.

**A2:** The ADF test checks if a time series has a unit root (non-stationary). Consider the AR(1) model: X_t = ρX_{t-1} + ε_t. If ρ = 1, we have a random walk (unit root). The ADF test regresses ΔX_t = α + βt + (ρ-1)X_{t-1} + Σγ_i ΔX_{t-i} + ε_t, where lags of ΔX account for serial correlation. The null hypothesis H₀: ρ = 1 (unit root) vs H₁: ρ < 1 (stationary). The test statistic is the t-statistic on (ρ-1), but it doesn't follow standard t-distribution under H₀—critical values are larger (more negative) than usual. If test statistic < critical value, reject H₀ (series is stationary). If not, fail to reject (series may be non-stationary). In finance, prices are often non-stationary (unit root), but returns (first differences) are typically stationary. The ADF test helps determine if differencing is needed before modeling.

## Q3: How do you identify AR versus MA processes using ACF and PACF?

**A3:** Autocorrelation function (ACF) measures correlation between X_t and X_{t-k} for various lags k. Partial autocorrelation function (PACF) measures correlation between X_t and X_{t-k} after removing effects of intermediate lags. For AR(p) processes: ACF decays exponentially (infinite tails), while PACF cuts off at lag p (PACF(k) = 0 for k > p). This is because AR models have infinite MA representation, creating ACF tails, but direct dependence only goes back p periods. For MA(q) processes: ACF cuts off at lag q (ACF(k) = 0 for k > q), while PACF decays exponentially. This is because MA models have finite memory (only last q shocks matter), but they have infinite AR representation. For ARMA(p,q): both ACF and PACF decay exponentially. In practice, use ACF/PACF plots: if ACF cuts off but PACF decays, it's MA. If PACF cuts off but ACF decays, it's AR. If both decay, consider ARMA.

## Q4: How do you select the appropriate ARIMA model?

**A4:** ARIMA(p,d,q) models combine AR(p), differencing of order d, and MA(q). Selection process: (1) Determine d: test for unit roots (ADF test). If non-stationary, difference; repeat until stationary. Usually d = 0 (returns) or d = 1 (prices). (2) Identify p and q: use ACF/PACF of differenced series. Look for cutoffs: PACF cuts off at p suggests AR(p), ACF cuts off at q suggests MA(q). (3) Information criteria: AIC = -2ln(L) + 2k or BIC = -2ln(L) + k ln(n), where k = p+q+1 parameters, n = sample size. Lower is better; BIC penalizes complexity more. (4) Diagnostic checks: test residuals for autocorrelation (Ljung-Box test), check if residuals are white noise, examine residual ACF/PACF. (5) Out-of-sample validation: compare forecast accuracy. Start simple (ARIMA(1,1,1)) and add complexity if needed. Overfitting is a risk, so prefer parsimonious models.

## Q5: What motivates GARCH models for volatility modeling?

**A5:** GARCH (Generalized Autoregressive Conditional Heteroskedasticity) models address volatility clustering: periods of high volatility tend to be followed by high volatility, and low by low. The GARCH(1,1) model specifies: σ²_t = ω + αε²_{t-1} + βσ²_{t-1}, where ε_t = σ_t z_t and z_t ~ iid(0,1). The term αε²_{t-1} captures reaction to recent shocks (ARCH effect), while βσ²_{t-1} captures persistence (GARCH effect). This creates time-varying volatility even with constant unconditional variance (if α + β < 1). Motivation: (1) Empirical: squared returns show autocorrelation, violating constant variance assumption. (2) Theoretical: information arrival is clustered, creating volatility clusters. (3) Risk management: accurate volatility forecasts need GARCH. (4) Option pricing: stochastic volatility models are GARCH-like. The model captures the "volatility of volatility" and mean reversion: long-term variance is ω/(1-α-β), and volatility reverts to this level.

## Q6: Compare EGARCH versus GJR-GARCH models.

**A6:** Both extend GARCH to capture asymmetric volatility (leverage effect: negative returns increase volatility more than positive returns). GJR-GARCH(1,1) uses: σ²_t = ω + αε²_{t-1} + γI_{t-1}ε²_{t-1} + βσ²_{t-1}, where I_{t-1} = 1 if ε_{t-1} < 0, else 0. The parameter γ > 0 captures extra volatility from negative shocks. EGARCH uses: ln(σ²_t) = ω + α(|z_{t-1}| - E|z_{t-1}|) + γz_{t-1} + β ln(σ²_{t-1}), where z_t = ε_t/σ_t. The γz_{t-1} term creates asymmetry: if γ < 0, negative z (negative returns) increase log-volatility more. Key differences: (1) EGARCH models log-volatility, ensuring σ²_t > 0 without parameter restrictions. (2) EGARCH asymmetry is smoother (continuous function of z), while GJR is discrete (jump at zero). (3) EGARCH is more flexible but harder to estimate. Both capture leverage effect, but EGARCH is often preferred for its smoothness and guaranteed positivity.

## Q7: What's the difference between cointegration and correlation?

**A7:** Correlation measures linear association between two series at the same point in time: Corr(X_t, Y_t). It can be spurious if both series trend (even if unrelated). Cointegration means two non-stationary series have a stationary linear combination: if X_t and Y_t are I(1) (integrated of order 1, i.e., have unit roots), but Z_t = X_t - βY_t is I(0) (stationary), they are cointegrated. This implies a long-run equilibrium relationship: deviations from β are temporary and mean-reverting. Correlation can be high even without cointegration (spurious regression), or low even with cointegration (if short-term noise dominates). In pairs trading, cointegration is crucial: you trade the spread Z_t, betting it reverts to zero. Correlation alone doesn't guarantee this—the spread could drift forever. Testing cointegration uses Engle-Granger (regress one on other, test residuals for unit root) or Johansen procedure (for multiple series).

## Q8: Explain the Engle-Granger test for cointegration.

**A8:** The Engle-Granger two-step procedure tests if two I(1) series X_t and Y_t are cointegrated. Step 1: Regress Y_t = α + βX_t + u_t and save residuals û_t. If cointegrated, û_t should be stationary (I(0)). Step 2: Test û_t for unit root using ADF test (but with modified critical values, since û_t are estimated residuals, not observed). If ADF rejects unit root, conclude cointegration exists with cointegrating vector (1, -β). Limitations: (1) Assumes one cointegrating relationship (for two series, this is fine). (2) Results depend on which variable is dependent (asymmetric). (3) Critical values differ from standard ADF (must use Engle-Granger tables). (4) Doesn't work for more than two series well. Advantages: Simple, intuitive, easy to implement. For multiple series or to find all cointegrating relationships, use Johansen procedure instead, which tests the rank of the cointegration space.

## Q9: What is the Johansen procedure for testing cointegration?

**A9:** The Johansen procedure tests cointegration in a vector error correction model (VECM) framework for multiple series. Consider a VAR model: ΔX_t = ΠX_{t-1} + ΣΓ_i ΔX_{t-i} + ε_t, where X_t is a vector of I(1) series. If series are cointegrated, Π has reduced rank r < n (number of series). The procedure: (1) Estimate VAR, get estimate of Π. (2) Compute eigenvalues of a matrix derived from Π. (3) Test hypotheses: H₀: rank(Π) = r vs H₁: rank(Π) > r using trace test or maximum eigenvalue test. (4) If reject r = 0 but not r = 1, conclude one cointegrating relationship exists. The eigenvectors give cointegrating vectors. Advantages over Engle-Granger: (1) Handles multiple series. (2) Finds all cointegrating relationships. (3) Symmetric (doesn't depend on normalization). (4) Provides estimates of adjustment speeds. Used in portfolio optimization (finding cointegrated assets) and macro-finance models.

## Q10: Explain Granger causality and how to test it.

**A10:** Granger causality tests if past values of X help predict Y beyond what Y's own past provides. It's about predictive ability, not true causation. To test if X Granger-causes Y: (1) Estimate restricted model: Y_t = α + Σβ_i Y_{t-i} + ε_t. (2) Estimate unrestricted: Y_t = α + Σβ_i Y_{t-i} + Σγ_i X_{t-i} + u_t. (3) Test H₀: all γ_i = 0 using F-test or likelihood ratio test. If reject H₀, X Granger-causes Y. Note: (1) Granger causality can be bidirectional (X causes Y and Y causes X). (2) It requires stationarity (or cointegration if series are I(1)). (3) It's sensitive to lag length choice (use information criteria). (4) Omitted variables can create spurious causality. In finance, test if volume Granger-causes returns, or if one asset's returns predict another's. It's useful for understanding lead-lag relationships and information flow, but doesn't imply structural causation.

## Q11: What is spurious regression and how do you avoid it?

**A11:** Spurious regression occurs when two independent non-stationary series appear correlated due to common trends, not true relationship. For example, regressing one random walk on another unrelated random walk can yield high R² and significant t-statistics, even though they're independent. The problem: standard t and F tests assume stationarity; with I(1) series, test statistics don't follow standard distributions, leading to false rejections. Solutions: (1) Difference series to make them stationary before regression. (2) Test for cointegration: if cointegrated, levels regression is valid (error correction model). (3) Use VAR in differences or VECM if cointegrated. (4) Check residuals: if regression of I(1) on I(1) produces I(0) residuals, relationship may be valid (cointegration). Red flags: very high R² with I(1) series, Durbin-Watson statistic near 0 (suggests non-stationary residuals), or visual inspection showing common trends. Always test for stationarity before regression.

## Q12: Provide intuition for the Kalman filter.

**A12:** The Kalman filter is a recursive algorithm that estimates unobservable state variables (like true volatility, or a time-varying parameter) from noisy observations. It works in two steps: (1) Prediction: given current state estimate, predict next state and its uncertainty using the state equation. (2) Update: when new observation arrives, combine prediction with observation (weighted by their uncertainties) to get updated state estimate. The weights come from minimizing mean squared error. Intuition: if observation is very noisy, trust prediction more; if prediction is uncertain, trust observation more. The filter provides optimal estimates (in MSE sense) under linearity and normality assumptions. In finance, use it for: (1) Estimating stochastic volatility from observed prices. (2) Time-varying parameter models (e.g., time-varying betas). (3) Factor models with unobservable factors. (4) Combining forecasts from multiple models. The Kalman filter handles missing data naturally and provides uncertainty estimates (filtered variance), crucial for risk management.

## Q13: What are regime-switching models and when are they useful?

**A13:** Regime-switching models allow parameters to change across different "regimes" or states (e.g., high-volatility vs low-volatility periods). The Markov-switching model assumes the regime follows a Markov chain: P(S_t = j | S_{t-1} = i) = p_{ij}, where S_t is the regime at time t. In each regime, the process has different parameters (mean, volatility, etc.). For example, returns might be r_t = μ_{S_t} + σ_{S_t}ε_t, where μ and σ depend on regime. Estimation uses the Hamilton filter (similar to Kalman filter but for discrete states) to compute probabilities of being in each regime. Advantages: (1) Captures structural breaks and regime changes naturally. (2) Models volatility clustering as regime persistence. (3) More flexible than constant-parameter models. Applications: (1) Business cycle modeling (expansion vs recession). (2) Volatility regimes (calm vs crisis). (3) Market microstructure (normal vs stressed). Challenges: (1) Hard to identify regimes in real-time. (2) Estimation is complex (EM algorithm). (3) Risk of overfitting with too many regimes.

## Q14: What methods are used for volatility forecasting?

**A14:** Common methods include: (1) Historical volatility: rolling window of past returns, σ² = (1/n)Σr²_{t-i}. Simple but backward-looking. (2) GARCH models: σ²_{t+1} = ω + αr²_t + βσ²_t provides one-step-ahead forecast. Multi-step requires iterating or using long-run variance. (3) Realized volatility: sum of squared intraday returns, RV_t = Σr²_{i,t} over day t. More accurate than daily squared returns. (4) Implied volatility: extract from option prices (market's forecast). Often best predictor but requires liquid options. (5) HAR (Heterogeneous Autoregressive) model: regress realized vol on its lags at different frequencies (daily, weekly, monthly) to capture multi-scale dynamics. (6) Combination forecasts: average multiple methods (GARCH, realized vol, implied vol) often outperforms individual methods. (7) Machine learning: use features (past returns, volume, etc.) to predict volatility. For risk management, GARCH and realized volatility are standard; for option pricing, implied volatility is primary.

## Q15: What's the difference between realized volatility and implied volatility?

**A15:** Realized volatility (RV) is ex-post measure computed from actual returns: RV_t = √(Σr²_{i,t}) where r_{i,t} are intraday returns on day t. It measures what volatility actually was. Implied volatility (IV) is ex-ante measure extracted from option prices using Black-Scholes (or other models): it's the volatility that makes model price equal market price. IV represents market's expectation of future volatility. Key differences: (1) Timing: RV is backward-looking (what happened), IV is forward-looking (what's expected). (2) Data: RV uses historical returns, IV uses current option prices. (3) Horizon: RV measures past period, IV measures option's remaining life. (4) Information: IV incorporates all available information (including future expectations), while RV only uses past data. In practice, IV is often a better predictor of future RV than past RV, but there's a volatility risk premium: IV tends to exceed realized vol on average (investors pay premium for volatility insurance). The difference IV - RV is the volatility risk premium.

## Q16: Explain the HAR model for volatility forecasting.

**A16:** The Heterogeneous Autoregressive (HAR) model regresses realized volatility on its own lags at different frequencies: RV_{t+1} = β₀ + β_d RV_t + β_w RV_{t-4:t} + β_m RV_{t-21:t} + ε_{t+1}, where RV_{t-4:t} is weekly average (past 5 days) and RV_{t-21:t} is monthly average (past 22 days). The model captures heterogeneous expectations: traders react to different time horizons (daily traders vs monthly investors). It's essentially an AR(22) with restrictions (only three coefficients), making it parsimonious yet flexible. The HAR model performs well empirically because: (1) It captures long memory in volatility (slow decay of autocorrelation). (2) It's simple to estimate (OLS regression). (3) It matches how traders actually think (multiple timeframes). Extensions include HAR-GARCH (add GARCH terms), HAR with jumps (separate continuous and jump components), and multivariate HAR (for covariance forecasting). It's widely used in high-frequency finance and risk management.

## Q17: How do you evaluate volatility forecasts (Diebold-Mariano test)?

**A17:** The Diebold-Mariano (DM) test compares forecast accuracy of two models. For forecasts ŷ_{1,t} and ŷ_{2,t} with actuals y_t, compute loss differential d_t = L(e_{1,t}) - L(e_{2,t}), where e_{i,t} = y_t - ŷ_{i,t} and L is loss function (e.g., squared error, absolute error). Under null H₀: E[d_t] = 0 (equal forecast accuracy), the DM statistic is DM = d̄ / SE(d̄), where d̄ is sample mean and SE accounts for serial correlation in d_t (since forecast errors are often autocorrelated). DM ~ N(0,1) asymptotically. If |DM| > 1.96, reject H₀ (one forecast is significantly better). Key points: (1) Accounts for forecast error dependence (important for time series). (2) Works for any loss function. (3) Asymptotic, so needs sufficient sample size. (4) More robust than comparing R² or MSE directly. Alternatives include model confidence set (tests multiple models) and out-of-sample R². Always use out-of-sample evaluation to avoid overfitting.

## Q18: How do you perform cross-validation for time series data?

**A18:** Standard k-fold CV fails for time series because it uses future data to predict past (look-ahead bias). Proper methods: (1) Forward chaining (time series split): train on [1:t], test on [t+1], then train on [1:t+1], test on [t+2], etc. This respects temporal order. (2) Walk-forward analysis: similar but with fixed training window that slides forward. (3) Purged k-fold: divide time into k folds, but ensure no overlap between training and test periods (purge gap between them to avoid leakage). (4) Blocked cross-validation: use blocks of consecutive observations, but still maintain temporal order. Key principles: (1) Never use future to predict past. (2) Account for dependence: if data is highly correlated, need longer gaps. (3) Use multiple train-test splits to get robust estimates. (4) Consider regime stability: if regimes change, recent data may be more relevant. For financial data, walk-forward with purging is standard, as it mimics real trading (train on past, test on future, update as new data arrives).

## Q19: How do you detect and handle structural breaks in time series?

**A19:** Structural breaks are sudden changes in model parameters (mean, variance, relationships). Detection methods: (1) Chow test: test if parameters differ before/after suspected break point. (2) CUSUM test: cumulative sum of residuals; if parameters stable, CUSUM stays within bounds. (3) Bai-Perron test: tests for multiple unknown break points. (4) Visual inspection: plot series, look for obvious shifts. Handling approaches: (1) Dummy variables: include indicator for post-break period in regression. (2) Split sample: estimate separate models for each regime. (3) Rolling window: use only recent data (assumes parameters constant in window). (4) Regime-switching models: allow parameters to switch probabilistically. (5) Robust methods: use estimators less sensitive to breaks. In finance, breaks occur from: policy changes, crises, market microstructure shifts. Important to test for breaks before using long historical samples, as old data may not be relevant. Out-of-sample testing helps detect if breaks affected model performance.

## Q20: Explain VAR impulse response functions.

**A20:** A Vector Autoregression (VAR) models multiple time series where each depends on lags of all series: X_t = A₁X_{t-1} + ... + A_pX_{t-p} + ε_t, where X_t is a vector. Impulse response functions (IRFs) trace how a one-unit shock to one variable affects all variables over time. To compute: (1) Estimate VAR, get coefficient matrices A_i and covariance matrix Σ of errors. (2) Use Cholesky decomposition: Σ = PP', so P^{-1}ε_t are orthogonal shocks. (3) IRF(h) = ∂X_{t+h}/∂ε_{j,t} shows response of all variables h periods after shock to variable j. IRFs show: (1) Magnitude: how large is the response? (2) Persistence: how long does effect last? (3) Sign: positive or negative effect? (4) Cross-effects: how do other variables respond? In finance, use IRFs to understand: (1) How monetary policy shocks affect asset prices. (2) Spillovers between markets. (3) Lead-lag relationships. Note: IRFs depend on variable ordering in Cholesky (identifying assumption). Alternative: use structural VAR with economic restrictions, or generalized IRFs that don't require ordering.
